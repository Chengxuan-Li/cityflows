# TASK-008 — Project persistence

Owner: unassigned
Gate: 1
Depends on: TASK-001

## Goal

Save and open projects as `.cityflows` ZIP archives and as single JSON documents with a
manifest, per-file hashes, Zod validation, and the migration entry point, as in architecture
section 12. The canonical `City` snapshot is the authoritative state; history is optional.

## In scope

- `src/project/`: `manifest.ts`, `save.ts` (`saveProject(project): Promise<Uint8Array>`,
  `saveProjectJson(project): string`), `open.ts` (`openProject(bytes | string):
  Promise<OpenResult>`), `hash.ts` (SHA-256 via WebCrypto, available in Node 22 and
  browsers), `zip.ts` (fflate wrappers), `types.ts` (`Project = { city, population, scenarios,
  history, view }`).
- `fixtures/projects/grid5x5.cityflows.json`: the Gate 1 demo project, generated by a script
  in `src/fixtures/scenarios.ts` and checked in.
- `tests/project/`.

## Out of scope

- UI file dialogs (TASK-009).
- GeoJSON and CSV exports (TASK-025, TASK-043).

## Interfaces

Section 12 layout. `OpenResult = { ok: true; project } | { ok: false; file: string; error:
string }` where `error` names the first failing Zod path or the hash mismatch.

## Acceptance tests

- `tests/project/T14-round-trip.test.ts`: save `grid5x5` with one edit and a population to
  ZIP, open it, compare city, scenarios and population deep-equal; run both compiled cities
  through 500 engine steps (engine from TASK-003 if merged, else compare compiled cities
  only) and compare hashes; same for the JSON form.
- `tests/project/errors.test.ts`: a tampered `city.json` fails on hash mismatch naming the
  file; a city with an invalid connector fails naming the Zod path; a missing `scenarios.json`
  fails; a project without `history.json` opens.
- `tests/project/migrate.test.ts`: opening `fixtures/projects/grid5x5.cityflows.json` works
  and `migrateCity` is invoked with `schemaVersion: 1`.

## Commands

`npm run check`

## Deliverable

PR with persistence, the checked-in fixture project and tests.
